Use xipos for subtree_com of massless subtrees

Google DeepMind, mujoco_warp #1844

context

MuJoCo Warp is the GPU version of the MuJoCo physics engine. For each body it computes the centre of mass of that body and everything attached below it, by summing mass times position and dividing by the total mass. A body with no mass, such as one that only holds a sensor, gave a total mass of zero, so the division was skipped and its centre of mass stayed at the origin of the world.

change

When the mass is below MuJoCo's small-number threshold, the kernel now uses the body's own position (xipos) instead, as the CPU MuJoCo does. The call site passes xipos in. The added test builds a hinged arm with a massless child and compares the result with MuJoCo; it fails before the change.

Erdős Problem 739 in Lean

Google DeepMind, formal-conjectures #7703

context

Formal Conjectures collects open maths problems written in Lean, a language in which statements can be checked by a computer. Problem 739 asks: if a graph needs infinitely many colours, m of them, so that no two neighbours share a colour, does it contain a smaller graph that needs exactly n colours for every infinite n below m?

change

The file states the question with Mathlib's chromaticCardinal and G.Subgraph, plus three variants: the n = ℵ₀ case (solved, from de Bruijn and Erdős), the induced-subgraph version (Galvin showed it implies 2^κ < 2^μ), and the question under the Generalized Continuum Hypothesis (open). The proofs are left as sorry, as the project does for open problems. The docstring records that Komjáth showed the statement is not provable in standard set theory.

Make start_now's request_stop reach its senders

NVIDIA, stdexec #2417

context

stdexec is NVIDIA's implementation of std::execution, the C++26 model for asynchronous work. start_now launches several tasks (senders) at once and returns a handle with request_stop() to cancel them. Each task was wrapped by the async scope with nest(), which replaces the task's stop signal with the scope's, so calling request_stop() on the handle never reached the tasks.

change

Each sender is first wrapped with __stop_when and the handle's own stop token, and only then nested in the scope. The task now listens to both signals. The library's counting scopes and spawn_future already used __stop_when the same way.

Google DeepMind, mujoco #3354

context

MuJoCo has two renderers. KTX texture files are stored as a single-channel block of bytes meant for the newer Filament renderer. The classic OpenGL renderer only handles RGB or RGBA images, and on any other channel count it called mju_error, which ends the program, so loading a model with a KTX texture crashed the viewer.

change

A check at the top of mjr_uploadTexture skips textures that are not 3 or 4 channels and prints a warning. Because the check runs first, the later else branch can assume 4 channels and the old error is gone. The check also covers cube maps, which had been reading the single-channel data as RGB.
